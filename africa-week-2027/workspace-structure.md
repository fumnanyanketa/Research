# Shared Workspace — proposed structure

A single home for everything Africa Week 2027 (and the team's other work), so nobody re-explains things and new people self-onboard. Recommended: **Google Drive** (the team already uses Google Docs for transcripts; lowest friction). Notion is a good alternative if the team wants databases/boards.

## What goes where

- **START HERE** + **Master Plan** sit at the top so a newcomer reads two docs and is oriented.
- **Meetings** — every recording → transcript → a short synthesis + action items, dated. This is the "memory" that stops ideas evaporating.
- **Workstreams** — each area gets one living doc owned by its owner: current status, tasks, decisions. Owners update their own.
- **Ideas** — one running log anyone can add to between meetings (feeds future agendas).
- **Funding** — a simple tracker (funder · deadline · amount · status) so applications start early, not last-minute.
- **Brand & assets** — single source of truth for logo, templates, photos (so everything looks consistent — part of the Slush-level polish).
- **Partners & contacts** — who we know, their role, and where the conversation stands.

## Access model (keep it simple)

- **Core team:** edit access to everything.
- **Volunteers:** edit access to their workstream + the idea log; view on the rest.
- **START HERE one-pager:** shareable "view" link for anyone being onboarded or invited.

## How it maps to what already exists

The planning docs already drafted (master plan, tech plan, action items, meeting syntheses, the one-pager, the capture template) are the **starting content** — they drop straight into this structure. The workspace is just the shared, living home for them where the whole team can see and contribute.

## Lightweight alternative

If a full Drive is too much for tomorrow, the minimum viable version is **three docs in one folder**: START HERE, the Master Plan, and a running Idea log + action items. Everything else can grow as the team does.
